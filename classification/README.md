### Выбор метрики

**Основная метрика качества: взвешенный F1-score (weighted F1).**

### Обоснование

- **Задача — многоклассовая классификация.** Целевая переменная `AdoptionSpeed` обычно кодирует скорость пристройства в несколько категорий (0–4). Метрика должна уметь работать с несколькими классами, а не только с двумя (как ROC-AUC в классическом варианте).

- **Классы, скорее всего, несбалансированы.** Обычно:
  - много животных с «средней» скоростью пристройства,
  - мало — с очень быстрой/очень медленной.
  В такой ситуации **Accuracy** может быть высокой даже у модели, которая «угадывает» только самый частый класс, и поэтому плохо отражает реальное качество.

- **F1-score учитывает и полноту, и точность.**  
  - Precision важен, чтобы не «обещать» быструю адаптацию тем, у кого она на самом деле медленная (ложноположительные).
  - Recall важен, чтобы не пропускать тех, у кого есть высокий шанс быстрого пристройства (ложноотрицательные).

- **Почему именно взвешенный (weighted F1), а не macro-F1.**  
  - **Weighted F1** усредняет F1 по классам, взвешивая по размеру класса → метрика устойчива к редким классам и соответствует «среднему качеству по объектам».
  - Он всё ещё учитывает все классы (в отличие от Accuracy, которая может «спрятать» ошибки на редких классах), но не делает редкие классы чрезмерно доминирующими в метрике.

Итого: **для базового уровня качества в этой задаче разумно взять `weighted F1-score` как основную метрику**, а Accuracy можно использовать как вспомогательную для интерпретации.

### Шаг 2. Ручной перебор параметров и логирование

На втором шаге проводится ручной перебор гиперпараметров модели `RandomForestClassifier` с использованием датасета `df_classification`, загруженного из Oracle. Для каждого набора параметров выполняются:

- **обучение модели** на train-выборке;
- **оценка качества** на validation-выборке по метрикам `weighted F1-score` (основная) и `Accuracy` (вспомогательная);
- **измерение времени обучения**.

Результаты каждого запуска (значения гиперпараметров, `weighted F1`, `Accuracy`, время обучения) логируются в базу данных SQLite в таблицу `rf_experiments`. Логирование реализовано двумя способами:

- в виде отдельного скрипта `train_random_forest_sqlite.py` в папке `classification/`;
- непосредственно в ноутбуке `models-comparison.ipynb`, где используется датафрейм `df_classification`.

Такой подход позволяет систематически сравнивать различные конфигурации `RandomForestClassifier`, анализировать результаты экспериментов через SQL-запросы и выбирать лучшие настройки модели по метрике `weighted F1-score`.

### Шаг 3. Регистрация модели

На третьем шаге по результатам логирования в SQLite выбирается лучший прогон `RandomForestClassifier` по метрике `weighted F1-score`. Его гиперпараметры считываются из таблицы `rf_experiments`, после чего модель с этими параметрами дообучается на всей доступной выборке признаков `X` и целевой переменной `y`.

Для управления экспериментами и артефактами используется **MLflow**:

- создаётся (или используется существующий) эксперимент `Pet-Adoption-RF-Baseline`;
- в рамках нового запуска в MLflow логируются лучшие гиперпараметры, метрики (`weighted F1-score`, `Accuracy`, время обучения);
- обученная модель регистрируется в **Model Registry** под именем `model-rf-baseline` через `mlflow.sklearn.log_model`.

Таким образом, базовая модель случайного леса фиксируется в реестре моделей как эталонная конфигурация (`model-rf-baseline`), к которой можно обращаться из других частей проекта и сравнивать с более продвинутыми моделями.

### Шаг 4. XGBoost: улучшение базового бейзлайна

На четвёртом шаге для улучшения качества относительно случайного леса используется бустинг над деревьями `XGBoost` (`XGBClassifier`). В ноутбуке `models-comparison.ipynb` создаётся отдельный эксперимент MLflow `Pet-Adoption-XGBoost`, в рамках которого выполняется перебор гиперпараметров (число деревьев, глубина, скорость обучения, доля объектов и признаков на дерево).

Для каждого набора гиперпараметров:

- **обучение модели** на train-выборке (`X_train`, `y_train`);
- **оценка качества** на validation-выборке (`X_valid`, `y_valid`) по метрикам `weighted F1-score` и `Accuracy`;
- **логирование** параметров, метрик и самой модели в MLflow (`mlflow.xgboost.log_model`).

В конце выбирается лучший набор гиперпараметров по `weighted F1-score`, что позволяет сравнить XGBoost с базовым `RandomForestClassifier`.

### Шаг 5. CatBoost: альтернативный градиентный бустинг

На пятом шаге тестируется ещё одна реализация градиентного бустинга — `CatBoostClassifier`. Для неё создаётся отдельный эксперимент MLflow `Pet-Adoption-CatBoost`, в котором по сетке перебираются гиперпараметры (число итераций, глубина деревьев, скорость обучения, L2-регуляризация листьев).

Для каждого набора гиперпараметров:

- **обучение модели CatBoost** на тех же разбиениях `X_train`, `y_train`;
- **оценка качества** на `X_valid`, `y_valid` по метрикам `weighted F1-score` и `Accuracy`;
- **логирование** параметров, метрик и обученной модели в MLflow (`mlflow.catboost.log_model`).

Это даёт возможность напрямую сравнить три семейства моделей (RandomForest, XGBoost, CatBoost) в единой системе отслеживания экспериментов и выбрать лучшую модель по целевой метрике `weighted F1-score`.

### Шаг 6. Регистрация финальной challenger-модели

На шестом шаге по результатам всех экспериментов (RandomForest, XGBoost, CatBoost) в MLflow ищется абсолютно лучший прогон по метрике `f1_weighted_valid`. С помощью `MlflowClient` выбирается соответствующий `run_id`, считываются его параметры и определяется тип модели (случайный лес, XGBoost или CatBoost).

Далее модель с найденными гиперпараметрами дообучается на всей доступной выборке признаков `X` и целевой переменной `y`, после чего:

- в отдельном эксперименте `Pet-Adoption-Challenger-Best` логируются исходные параметры лучшего прогона и его метрики валидации;
- финальная модель логируется и регистрируется в MLflow Model Registry под именем `model-challenger-best`.

Таким образом, в реестре моделей фиксируется не только базовая модель (`model-rf-baseline`), но и **лучший на текущий момент challenger**, полученный на основе сравнения всех протестированных подходов.

### Общие результаты и выводы

- **Выбранная метрика качества**: в качестве основной метрики использован `weighted F1-score`, так как задача является многоклассовой и несбалансированной; метрика учитывает и точность, и полноту по всем классам и менее чувствительна к дисбалансу, чем `Accuracy`.

- **Бейзлайн-модель**: в роли базовой модели выступает `RandomForestClassifier`. Лучший результат на валидации получен при параметрах  
  `{'n_estimators': 100, 'max_depth': None, 'min_samples_split': 2, 'min_samples_leaf': 2, 'criterion': 'entropy', 'random_state': 42}`  
  с качеством `weighted F1-score = 0.3940` и `Accuracy ≈ 0.4095`. Эта модель зарегистрирована в MLflow Model Registry под именем `model-rf-baseline`.

- **Альтернативные модели**: для улучшения качества были протестированы два градиентных бустинга над деревьями: `XGBoost` (`XGBClassifier`) и `CatBoostClassifier`. Для каждой модели настроены отдельные эксперименты в MLflow (`Pet-Adoption-XGBoost`, `Pet-Adoption-CatBoost`) и выполнен перебор гиперпараметров с логированием параметров, метрик и самих моделей.

- **Лучшая альтернативная модель**: среди альтернатив наилучший результат показал `XGBoost` с параметрами  
  `{'n_estimators': 200, 'max_depth': 7, 'learning_rate': 0.1, 'subsample': 0.8, 'colsample_bytree': 0.8}`  
  и качеством `weighted F1-score = 0.3874` (чуть ниже бейзлайна). Для `CatBoost` лучшая конфигурация  
  `{'iterations': 400, 'depth': 6, 'learning_rate': 0.1, 'l2_leaf_reg': 5}`  
  дала `weighted F1-score = 0.3804`.

- **Итоговый вывод**: по целевой метрике `weighted F1-score` улучшить качество **относительно бейзлайна RandomForest не удалось** — лучшая модель XGBoost немного уступает базовой (0.3874 против 0.3940), а CatBoost показывает ещё более низкий результат. Поэтому в качестве финальной модели-challenger, зарегистрированной как `model-challenger-best`, остаётся конфигурация случайного леса из бейзлайна, подтверждённая сравнением с бустингами.
